## Agent Anatomy

An agent is a single Markdown file in `agents/` — YAML frontmatter that tells Claude Code when to delegate, followed by the agent's system prompt.

```yaml
---
name: code-reviewer
description: >
  Use this agent for senior-level review of a PR, branch, or diff.
  Trigger on "review this PR", "review my branch", "is this safe to merge".
tools: Bash, Read, Grep, Glob
model: inherit
color: red
memory: project
---
You are a senior code reviewer...
```

## Frontmatter Reference

| Field | Required | Values | Notes |
| --- | --- | --- | --- |
| `name` | yes | kebab-case identifier | How the agent is referenced and where its memory lives. |
| `description` | yes | free text | Drives delegation — include explicit trigger phrases and what the agent returns. |
| `tools` | no | comma-separated tool names | Omit to inherit all tools. List only what the agent needs (e.g. `Bash, Read, Grep, Glob` for read-only agents). |
| `model` | no | model name or `inherit` | Default is `inherit` (uses the conversation's model). |
| `color` | no | `red`, `blue`, `green`, `yellow`, `purple`, `orange`, `pink`, `cyan` | Display color in the UI. Nexus uses it to group agents by domain. |
| `memory` | no | `user`, `project`, `local` | Enables persistent memory at that scope (see below). |

## Persistent Memory

Every Nexus agent declares a `memory` scope. The first 200 lines of the agent's `MEMORY.md` are auto-injected at session start, and `Read`/`Write`/`Edit` are auto-enabled so the agent can maintain its own memory files.

| Scope | Lives | Use for |
| --- | --- | --- |
| `user` | per-user, portable across every repo | Personal preferences, recurring stack choices, review style. |
| `project` | per-repo, in `.claude/agent-memory/` | Repo conventions, architecture learnings, known stubs. Shared with the team if committed. |
| `local` | per-repo, never committed | Machine-specific or private context. |

Rule of thumb: agents that adapt to *you* (designers, planners, reviewers of your taste) use `user`; agents that adapt to *a codebase* (architecture, database, code review) use `project`.

## Writing A Good Description

The `description` field is the delegation contract. The shipped agents follow a consistent shape:

- Start with "Use this agent to/for ..." and the task domain.
- List literal trigger phrases users actually type.
- State what the agent returns (verdict, table, plan) so the caller knows the output shape.
- Declare constraints, e.g. "Read-only — it never edits code."

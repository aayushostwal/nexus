## Fix Your First Issue

[Install Nexus](/docs/getting-started/installation), open a local Git repository, and configure GitHub access through your host's connector or authenticated `gh` CLI. In Claude Code:

```text
/nexus:software-engineer fix issue #123 in the current repository and raise a PR
```

You can also give a local directory and a concrete bug:

```text
Use software-engineer in /path/to/repo. Saving an empty display name crashes. Reproduce the bug, fix it, run relevant checks, and raise a PR.
```

With a directory but no issue, the workflow inspects open GitHub issues and selects a bounded candidate according to its selection rules. It checks for existing work, protects unrelated changes, investigates, implements, verifies, and opens a focused PR. Missing authentication or failed checks are reported; a successful local check does not establish green CI. The workflow does not merge or deploy.

In Codex, select the installed software-engineer skill or ask for it by name. Exact invocation and agent support depend on your host and installer.

## Try A Small Command

After staging a change intentionally, ask Claude Code to draft a commit message:

```text
/nexus:commit-message
```

The command drafts a message from the staged diff. If nothing is staged, it reports that condition.

## Trigger A Skill Or Agent

```text
/nexus:debugging investigate the failing CI pipeline
```

In Claude Code, ask to use `code-reviewer` for a read-only PR review or `codebase-explorer` to locate an implementation. Agent memory and tool permissions are host-specific. Instructions to stay read-only do not replace host permission enforcement.
